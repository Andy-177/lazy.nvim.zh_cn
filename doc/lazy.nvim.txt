1. 📰 新增了什么                         *lazy.nvim-📰-what’s-new?*


11.X                                       *lazy.nvim-📰-what’s-new?-11.x*

- **全新网站**：网站焕然一新，文档也得到了改进。
    前往 <https://lazy.folke.io> 看看吧。GitHub 上的 `README.md`
    也已更新为指向新网站。`vimdoc` 中包含了网站上提供的全部信息。
- **Spec 解析与合并**：从插件的各个片段解析出最终 spec 的代码已被重写。
    这应该会快上那么一点点，但更重要的是，它修复了一些问题，而且更易于维护。
- 软件包 <https://lazy.folke.io/packages> 现在可以用以下任一方式
    指定它们的依赖和配置：
    - **Lazy**：`lazy.lua` 文件
    - **Rockspec**：luarocks <https://luarocks.org/> 的 `*-scm-1.rockspec` 文件 <https://github.com/luarocks/luarocks/wiki/Rockspec-format>
    - **Packspec**：`pkg.json`（实验性功能，因为该格式 <https://github.com/neovim/packspec/issues/41> 尚未完全成熟）
    相关的 _lazy.nvim_ 选项：
    >lua
        {
          pkg = {
            enabled = true,
            cache = vim.fn.stdpath("state") .. "/lazy/pkg-cache.lua",
            -- 插件找到的第一个可用的包源将被使用。
            sources = {
              "lazy",
              "rockspec", -- 仅当 rocks.enabled 为 true 时才会使用
              "packspec",
            },
          },
          rocks = {
            enabled = true,
            root = vim.fn.stdpath("data") .. "/lazy-rocks",
            server = "https://nvim-neorocks.github.io/rocks-binaries/",
          },
        }
    <
- 安装 neorg <https://github.com/nvim-neorg/neorg> 现在非常简单：
    >lua
        { "nvim-neorg/neorg", opts = {} }
    <
- 软件包不再局限于 Neovim 插件。你可以安装任意
    **luarocks** 软件包，例如：
    >lua
        { "https://github.com/lubyk/yaml" }
    <
    不带 `/lua` 目录的 Luarocks 软件包永远不会被延迟加载，因为
    它只是一个库。
- `build` 函数或 `*.lua` 构建文件（例如 `build.lua`）现在会
    异步运行。你可以用 `coroutine.yield(status_msg)` 来显示进度。
    让出执行权还会把下一次 `resume` 调度到下一个 tick，因此你
    可以执行耗时较长的任务而不会阻塞 Neovim。

2. 🚀 快速上手                            *lazy.nvim-🚀-getting-started*

**lazy.nvim** 是一个用于 Neovim 的现代化插件管理器。


✨ 特性                            *lazy.nvim-🚀-getting-started-✨-features*

- 📦 用强大的 UI 管理你所有的 Neovim 插件
- 🚀 借助自动缓存以及 Lua 模块的字节码编译，获得极快的启动速度
- 💾 使用部分克隆而非浅克隆
- 🔌 自动延迟加载 Lua 模块，并支持按事件、命令、文件类型和快捷键映射延迟加载
- ⏳ 在启动 Neovim 之前自动安装缺失的插件，让你能够立刻开始使用
- 💪 异步执行以提升性能
- 🛠️ 无需手动编译插件
- 🧪 正确处理依赖关系的执行顺序
- 📁 可在多个文件中进行配置
- 📚 为没有 vimdoc 的插件，根据其 `README.md` 文件中的标题生成 helptags
- 💻 用于使用本地插件的 dev 选项与模式匹配
- 📊 用于优化性能的性能分析工具
- 🔒 锁文件 `lazy-lock.json`，用于记录已安装的插件
- 🔎 自动检查更新
- 📋 支持 commit、branch、tag、version 以及完整的 Semver <https://devhints.io/semver>
- 📈 状态栏组件，用于显示待处理更新的数量
- 🎨 自动延迟加载配色方案


⚡️ 环境要求        *lazy.nvim-🚀-getting-started-⚡️-requirements*

- Neovim >= **0.8.0**（必须使用 **LuaJIT** 构建）
- Git >= **2.19.0**（用于支持部分克隆）
- 一个 Nerd Font <https://www.nerdfonts.com/> 字体 **（可选）**
- luarocks <https://luarocks.org/>，用于安装 rockspec。
    你可以从 `opts.pkg.sources` 中移除 `rockspec` 来禁用此功能。

3. 🛠️ 安装                                *lazy.nvim-🛠️-installation*

安装 **lazy.nvim** 有多种方式。**结构化安装**是推荐的方式，
但如果你更喜欢把所有内容都放在 `init.lua` 里，也可以使用**单文件安装**。

所有可用选项的概览，请参阅「配置」</configuration>一节。




结构化安装                 *lazy.nvim-🛠️-installation-structured-setup*

>lua
    require("config.lazy")
<

>lua
    -- 引导安装 lazy.nvim
    local lazypath = vim.fn.stdpath("data") .. "/lazy/lazy.nvim"
    if not (vim.uv or vim.loop).fs_stat(lazypath) then
      local lazyrepo = "https://github.com/folke/lazy.nvim.git"
      local out = vim.fn.system({ "git", "clone", "--filter=blob:none", "--branch=stable", lazyrepo, lazypath })
      if vim.v.shell_error ~= 0 then
        vim.api.nvim_echo({
          { "克隆 lazy.nvim 失败：\n", "ErrorMsg" },
          { out, "WarningMsg" },
          { "\n按任意键退出……" },
        }, true, {})
        vim.fn.getchar()
        os.exit(1)
      end
    end
    vim.opt.rtp:prepend(lazypath)
    
    -- 请确保在加载 lazy.nvim 之前先设置好 `mapleader` 和 `maplocalleader`，
    -- 这样快捷键映射才是正确的。
    -- 这里也是设置其他选项（vim.opt）的好地方
    vim.g.mapleader = " "
    vim.g.maplocalleader = "\\"
    
    -- 设置 lazy.nvim
    require("lazy").setup({
      -- highlight-start
      spec = {
        -- 导入你的插件
        { import = "plugins" },
      },
      -- highlight-end
      -- 在这里配置其他设置。更多细节请参阅文档。
      -- 安装插件时要使用的配色方案。
      install = { colorscheme = { "habamax" } },
      -- 自动检查插件更新
      checker = { enabled = true },
    })
<

接下来你可以在 `~/.config/nvim/lua/plugins/` 中创建插件 spec。每个
文件都应返回一个表，其中包含你想安装的插件。

更多信息请参阅「组织你的插件」</usage/structuring>

4. 🔌 插件 Spec                               *lazy.nvim-🔌-plugin-spec*


SPEC 来源                           *lazy.nvim-🔌-plugin-spec-spec-source*

  -----------------------------------------------------------------------------------
  属性     类型       说明
  ---------- ---------- -------------------------------------------------------------
  [1]        string?    插件的简短 url。会使用
                        config.git.url_format 进行展开。也可以是 url 或目录。

  dir        string?    指向本地插件的目录

  url        string?    存放该插件的自定义 git url

  name       string?    插件的自定义名称，用于本地插件
                        目录，同时也是显示名称

  dev        boolean?   为 true 时，将改用本地插件目录。参见
                        config.dev
  -----------------------------------------------------------------------------------
一个合法的 spec 应当定义 `[1]`、`dir` 或 `url` 之一。


SPEC 加载                         *lazy.nvim-🔌-plugin-spec-spec-loading*

  --------------------------------------------------------------------------------------------------
  属性         类型                      说明
  -------------- ------------------------- ---------------------------------------------------------
  dependencies   LazySpec[]                插件加载时应当一同加载的插件名称或插件 spec 列表。依赖总是
                                            会被延迟加载，除非另有说明。在指定名称时，请确保该插件的
                                            spec 已在其他地方定义过。

  enabled        boolean? or fun():boolean 为 false 时，或当该函数返回 false 时，这个
                                            插件将不会被包含进 spec

  cond           boolean? or               行为与 enabled 相同，但条件为 false 时
                 fun(LazyPlugin):boolean   不会卸载插件。例如可用于在 vscode 或 firenvim 中
                                            禁用某些插件。

  priority       number?                   仅对启动时加载的插件（lazy=false）有用，用于强制
                                            优先加载某些插件。默认优先级为 50。
                                            建议为配色方案设置一个较高的数值。
  --------------------------------------------------------------------------------------------------

SPEC 设置                             *lazy.nvim-🔌-plugin-spec-spec-setup*

  --------------------------------------------------------------------------------------------------
  属性     类型                              说明
  ---------- ----------------------------- ---------------------------------------------------------
  init       fun(LazyPlugin)               init 函数总是在启动期间执行。主要
                                            用于设置 Vim 插件启动时所需的 vim.g.* 配置

  opts       table or                      opts 应为一个表（会与父级
             fun(LazyPlugin, opts:table)   spec 合并），也可以返回一个表（替换父级
                                            spec）或直接修改某个表。该表会被传给
                                            Plugin.config() 函数。设置此值即隐含
                                            Plugin.config()

  config     fun(LazyPlugin, opts:table)   config 会在插件加载时执行。默认
             or true                       实现会在设置了 opts 或 config = true 时，
                                            自动运行 require(MAIN).setup(opts)。
                                            Lazy 会依据插件的名称，使用若干启发式
                                            规则自动确定插件的 MAIN 模块。
                                            （推荐用 opts 来配置插件）。

  main       string?                       你可以指定 config() 和 opts() 所使用的
                                            主模块，以便在无法自动确定时使用。
                                            参见 config()

  build      fun(LazyPlugin) or string or  build 会在插件被安装或更新时执行。
             false or a list of build      更多信息参见「构建」一节。
             commands
  --------------------------------------------------------------------------------------------------
只要可能，请始终使用 `opts` 而不是 `config`。几乎从来都不需要
使用 `config`。




SPEC 延迟加载               *lazy.nvim-🔌-plugin-spec-spec-lazy-loading*

  --------------------------------------------------------------------------------------------------------------------
  属性     类型                                                             说明
  ---------- ---------------------------------------------------------------- ----------------------------------------
  lazy       boolean?                                                         为 true 时，插件只会在
                                                                               需要时才会加载。延迟加载的
                                                                               插件会在其 Lua 模块被 require，
                                                                               或某个延迟加载处理器被触发时
                                                                               自动加载

  event      string? or string[] or                                           按事件延迟加载。事件可以
             fun(self:LazyPlugin, event:string[]):string[] or                 直接写成 BufEnter，也可以带上
             {event:string[]\|string, pattern?:string[]\|string}              模式，例如 BufEnter *.lua

  cmd        string? or string[] or                                           按命令延迟加载
             fun(self:LazyPlugin, cmd:string[]):string[]


  ft         string? or string[] or                                           按文件类型延迟加载
             fun(self:LazyPlugin, ft:string[]):string[]


  keys       string? or string[] or LazyKeysSpec[] or                         按快捷键映射延迟加载
             fun(self:LazyPlugin, keys:string[]):(string \| LazyKeysSpec)[]
  --------------------------------------------------------------------------------------------------------------------
更多信息请参阅「延迟加载」一节 <./lazy_loading.md>。


SPEC 版本控制                   *lazy.nvim-🔌-plugin-spec-spec-versioning*

  ------------------------------------------------------------------------------
  属性     类型                 说明
  ------------ -------------------- --------------------------------------------
  branch       string?              仓库的分支

  tag          string?              仓库的标签

  commit       string?              仓库的提交

  version      string? or false to  要从仓库中使用的版本。支持完整的
               override the default Semver 版本范围

  pin          boolean?             为 true 时，此插件不会被纳入
                                     更新

  submodules   boolean?             为 false 时，不会获取 git 子模块。
                                     默认为 true
  ------------------------------------------------------------------------------
更多信息请参阅「版本控制」一节 <./versioning.md>。


SPEC 进阶                       *lazy.nvim-🔌-plugin-spec-spec-advanced*

  ----------------------------------------------------------------------------------------
  属性     类型       说明
  ---------- ---------- ------------------------------------------------------------------
  optional   boolean?   当一个 spec 被标记为 optional 时，只有当同一个插件曾在其他
                        某处不带 optional 地被指定过，它才会被包含进最终 spec。
                        这主要对 Neovim 发行版有用，便于为可能属于、也可能不属于
                        用户插件集的插件设置选项。

  specs      LazySpec   在插件作用域内定义的插件 spec 列表。这
                        主要对 Neovim 发行版有用，便于为可能属于、也可能不属于
                        用户插件集的插件设置选项。当该
                        插件被禁用时，这些作用域内的 spec 都不会被包含进
                        最终 spec。类似于 dependencies，但不会自动
                        加载这些 spec。

  module     false?     当它的 Lua 模块在某处被 require 时，不要自动加载它

  import     string?    导入给定的 spec 模块。
  ----------------------------------------------------------------------------------------

示例                                 *lazy.nvim-🔌-plugin-spec-examples*

>lua
    return {
      -- 启动 Neovim 时应当可以使用的配色方案
      {
        "folke/tokyonight.nvim",
        lazy = false, -- 如果这是你的主配色方案，确保在启动期间就加载它
        priority = 1000, -- 确保它在所有其他启动时加载的插件之前加载
        config = function()
          -- 在这里加载配色方案
          vim.cmd([[colorscheme tokyonight]])
        end,
      },
    
      -- 我有一个单独的 config.mappings 文件，里面 require 了 which-key。
      -- 使用 lazy 时，只要某处 require 了它，插件就会被自动加载
      { "folke/which-key.nvim", lazy = true },
    
      {
        "nvim-neorg/neorg",
        -- 按文件类型延迟加载
        ft = "norg",
        -- neorg 的选项。这会自动调用 `require("neorg").setup(opts)`
        opts = {
          load = {
            ["core.defaults"] = {},
          },
        },
      },
    
      {
        "dstein64/vim-startuptime",
        -- 按命令延迟加载
        cmd = "StartupTime",
        -- init 会在启动期间被调用。Vim 插件的配置通常应当在 init 函数中设置
        init = function()
          vim.g.startuptime_tries = 10
        end,
      },
    
      {
        "hrsh7th/nvim-cmp",
        -- 在 InsertEnter 时加载 cmp
        event = "InsertEnter",
        -- 这些依赖只有在 cmp 加载时才会被加载
        -- 依赖总是会被延迟加载，除非另有说明
        dependencies = {
          "hrsh7th/cmp-nvim-lsp",
          "hrsh7th/cmp-buffer",
        },
        config = function()
          -- ...
        end,
      },
    
      -- 如果某些代码 require 了某个尚未加载的插件的模块，它会被自动加载。
      -- 所以对于 devicons 这类 api 插件，我们总是可以设置 lazy=true
      { "nvim-tree/nvim-web-devicons", lazy = true },
    
      -- 对于可以晚点加载、且对初始界面并不重要的事情，
      -- 你可以使用 VeryLazy 事件
      { "stevearc/dressing.nvim", event = "VeryLazy" },
    
      {
        "Wansmer/treesj",
        keys = {
          { "J", "<cmd>TSJToggle<cr>", desc = "切换合并" },
        },
        opts = { use_default_keymaps = false, max_join_length = 150 },
      },
    
      {
        "monaqa/dial.nvim",
        -- 按快捷键映射延迟加载
        -- mode 默认为 `n`。有关更高级的选项，请查阅快捷键映射一节
        keys = { "<C-a>", { "<C-x>", mode = "n" } },
      },
    
      -- 本地插件需要用 dir 显式配置
      { dir = "~/projects/secret.nvim" },
    
      -- 你可以用自定义 url 来获取插件
      { url = "git@github.com:folke/noice.nvim.git" },
    
      -- 本地插件也可以用 dev 选项来配置。
      -- 这会使用 {config.dev.path}/noice.nvim/，而不是从 GitHub 获取
      -- 借助 dev 选项，你可以轻松地在本地版本和已安装版本之间切换
      { "folke/noice.nvim", dev = true },
    }
<


延迟加载                         *lazy.nvim-🔌-plugin-spec-lazy-loading*

**lazy.nvim** 会自动延迟加载 Lua 模块。这意味着，如果你有一个被延迟加载的
插件 `A`，以及一个 require 了插件 `A` 某个模块的插件 `B`，那么插件 `A`
就会如预期那样按需加载。


此外，你还可以按**事件**、**命令**、**文件类型**和**快捷键映射**来延迟加载。

当满足以下任一条件时，插件会被延迟加载：

- 该插件在你的 spec 中只作为依赖存在
- 它带有 `event`、`cmd`、`ft` 或 `keys` 字段
- `config.defaults.lazy == true`


🌈 配色方案 ~

配色方案插件可以配置为 `lazy=true`。执行 `colorscheme foobar` 时，该插件会
自动加载。



⌨️ 延迟加载的快捷键映射 ~

`keys` 属性可以是一个 `string` 或 `string[]`，用于简单的普通模式映射；
也可以是一个 `LazyKeysSpec` 表，包含以下键值对：

- **[1]**：（`string`）映射触发键 lhs **（必填）**
- **[2]**：（`string|fun()`）映射结果 rhs **（可选）**
- **mode**：（`string|string[]`）模式 **（可选，默认值为 "n"）**
- **ft**：（`string|string[]`）用于缓冲区本地映射的 `filetype` **（可选）**
- 任何其他对 `vim.keymap.set` 有效的选项

快捷键映射会在首次被执行时加载该插件。

当 `[2]` 为 `nil` 时，真正的映射必须由 `config()` 函数来创建。

>lua
    -- neo-tree.nvim 的示例
    {
      "nvim-neo-tree/neo-tree.nvim",
        keys = {
          { "<leader>ft", "<cmd>Neotree toggle<cr>", desc = "NeoTree" },
        },
        opts = {},
    }
<


版本控制                             *lazy.nvim-🔌-plugin-spec-versioning*

如果你想安装某个插件的特定修订版本，可以使用 `commit`、
`tag`、`branch`、`version`。

`version` 属性支持 Semver <https://semver.org/> 版本范围。



示例 ~

- `*`：最新的稳定版本（不含预发布版本）
- `1.2.x`：任何以 `1.2` 开头的版本，例如 `1.2.0`、`1.2.3` 等。
- `^1.2.3`：任何与 `1.2.3` 兼容的版本，例如 `1.3.0`、`1.4.5` 等，但不含 `2.0.0`。
- `~1.2.3`：任何与 `1.2.3` 兼容的版本，例如 `1.2.4`、`1.2.5`，但不含 `1.3.0`。
- `>1.2.3`：任何大于 `1.2.3` 的版本，例如 `1.3.0`、`1.4.5` 等。
- `>=1.2.3`：任何大于或等于 `1.2.3` 的版本，例如 `1.2.3`、`1.3.0`、`1.4.5` 等。
- `<1.2.3`：任何小于 `1.2.3` 的版本，例如 `1.1.0`、`1.0.5` 等。
- `<=1.2.3`：任何小于或等于 `1.2.3` 的版本，例如 `1.2.3`、`1.1.0`、`1.0.5` 等

5. 📦 软件包                                    *lazy.nvim-📦-packages*

**lazy.nvim** 支持三种方式让插件定义自己的依赖和配置。

- **Lazy**：`lazy.lua` 文件
- **Rockspec**：luarocks <https://luarocks.org/> 的 `*-scm-1.rockspec` 文件 <https://github.com/luarocks/luarocks/wiki/Rockspec-format>
- **Packspec**：`pkg.json`（实验性功能，因为该格式 <https://github.com/neovim/packspec/issues/41> 尚未完全成熟）

你可以通过 `config.pkg.sources`
</configuration> 启用/禁用包源。包源的顺序很重要，因为找到
软件包的那个包源会被优先使用。



Lazy                                            *lazy.nvim-📦-packages-lazy*

推荐使用 `lazy.lua` 文件来定义插件的依赖和配置。其语法与任何
插件 spec 完全相同。


Rockspec                                    *lazy.nvim-📦-packages-rockspec*

当一个插件包含 `*-1.rockspec` 文件时，**lazy.nvim** 会自动
构建该 rock 及其依赖。

只有满足以下条件之一时，才会使用 **rockspec**：

- 该软件包没有 `/lua` 目录
- 该软件包有复杂的构建步骤
- 该软件包有依赖（不含 `lua`）


Packspec                                    *lazy.nvim-📦-packages-packspec*

支持 pkg.json
<https://github.com/nvim-lua/nvim-package-specification/issues/41> 格式，并在
`lazy` 中提供一个 lazy 扩展。`lazy` 可以包含任意合法的 lazy spec 字段。它们
会被添加到插件的 spec 中。

7. 🚀 用法                                          *lazy.nvim-🚀-usage*


▶️ 启动顺序      *lazy.nvim-🚀-usage-▶️-startup-sequence*

**lazy.nvim** **不会**使用 Neovim 的软件包机制，甚至会完全禁用插件加载
（`vim.go.loadplugins = false`）。它接管了整个启动
流程，以获得更大的灵活性和更好的性能。

实际上这意味着 |Neovim Initialization| 的第 10 步由 Lazy 完成：

1. 执行所有插件的 `init()` 函数
2. 加载所有 `lazy=false` 的插件。这包括 source `/plugin` 和 `/ftdetect` 文件。（`/after` 此时还不会被 source）
3. source 你 rtp 中 `/plugin` 和 `/ftdetect` 目录下的所有文件（不包括 `/after`）
4. source 所有 `/after/plugin` 文件（这包括来自插件的 `/after`）

来自运行时目录的文件总是按字母顺序 source。



🚀 命令                            *lazy.nvim-🚀-usage-🚀-commands*

插件通过 `:Lazy` 命令管理。按 `<?>` 可以打开帮助，查看所有
快捷键映射。

你可以在某个插件上按 `<CR>` 来显示其详情。大多数属性都可以
用 `<K>` 悬停，以打开链接、帮助文件、readme、git 提交和 git
issue。

Lazy 可以在后台自动检查更新。此功能可以
通过 `config.checker.enabled = true` 启用。

任何操作都可以从 UI 发起，用子命令或 API
函数：

                                                             fetch）

`opts` 是一个包含以下键值的表：

- **wait**：为 true 时，该调用会等待操作完成
- **show**：为 false 时，不会显示 UI
- **plugins**：要对其执行该操作的插件名称列表
- **concurrency**：限制同时运行的任务 `number` 数量

📆 用户事件                 *lazy.nvim-🚀-usage-📆-user-events*

将会触发以下用户事件：

- **LazyDone**：当 lazy 完成启动并加载完你的配置时
- **LazySync**：执行 sync 之后
- **LazyInstall**：执行安装之后
- **LazyUpdate**：执行更新之后
- **LazyClean**：执行清理之后
- **LazyCheck**：检查更新之后
- **LazyLog**：执行 log 之后
- **LazyLoad**：加载插件之后。`data` 属性将包含插件名称。
- **LazySyncPre**：执行 sync 之前
- **LazyInstallPre**：执行安装之前
- **LazyUpdatePre**：执行更新之前
- **LazyCleanPre**：执行清理之前
- **LazyCheckPre**：检查更新之前
- **LazyLogPre**：执行 log 之前
- **LazyReload**：由变更检测在重新加载插件 spec 之后触发
- **VeryLazy**：在 `LazyDone` 之后并处理完 `VimEnter` 自动命令之后触发
- **LazyVimStarted**：在 `UIEnter` 之后且 `require("lazy").stats().startuptime` 计算完成之后触发。
    可用于更新你面板上的启动时间。


❌ 卸载                       *lazy.nvim-🚀-usage-❌-uninstalling*

要卸载 **lazy.nvim**，你需要删除以下文件和
目录：

- **data**：`~/.local/share/nvim/lazy`
- **state**：`~/.local/state/nvim/lazy`
- **lockfile**：`~/.config/nvim/lazy-lock.json`


  如果你修改过 `XDG` 环境变量，路径可能会有所不同。

🔒 锁文件                          *lazy.nvim-🚀-usage-🔒-lockfile*

每次 **update** 之后，本地锁文件（`lazy-lock.json`）都会用
已安装的修订版本更新。建议把这个文件纳入版本
控制。

如果你在多台机器上使用同一份 Neovim 配置，借助锁文件，你可以
确保每个插件都安装了相同的版本。

如果你换到了另一台机器上，可以执行 `:Lazy restore`，把所有插件
更新到锁文件中的版本。

PACKER.NVIM ~

- `setup` ➡️ `init`
- `requires` ➡️ `dependencies`
- `as` ➡️ `name`
- `opt` ➡️ `lazy`
- `run` ➡️ `build`
- `lock` ➡️ `pin`
- `disable=true` ➡️ `enabled = false`
- `tag='*'` ➡️ `version="*"`
- 对于大多数用例，`after` **并不需要**。否则请使用 `dependencies`。
- 对于大多数用例，`wants` **并不需要**。否则请使用 `dependencies`。
- `config` 不支持 string 类型，请改用 `fun(LazyPlugin)`。
- `module` 会被自动加载，无需指定
- `keys` spec 的写法与之前不同
- `rtp` 可以这样实现：

>lua
    config = function(plugin)
        vim.opt.rtp:append(plugin.dir .. "/custom-rtp")
    end
<

在 packer 中，可以用 `wants`、`requires` 和 `after` 来管理依赖。
而在 lazy 中，对于大多数 Lua 依赖并不需要这样做。它们可以像
普通插件一样安装（即使带有 `lazy=true`），并会在其他插件
需要它们时加载。可以用 `dependencies` 键把这些被依赖的插件
和需要它们的插件归为一组。被添加为
`dependencies` 的插件总是会被延迟加载，并在该插件
加载时被加载。

⚡ 性能分析与调试       *lazy.nvim-🚀-usage-⚡-profiling-&-debug*

启动代码（`lazy.core`）经过了精心设计，以确保尽可能高的
效率。在启动期间，`VimEnter` 或
`BufReadPre` 之前用到的所有 Lua 文件都会被字节编译并缓存，这与 impatient.nvim

**lazy.nvim** 自带一个高级性能分析器 `:Lazy profile`，帮助你
优化性能。性能分析视图会告诉你为什么加载插件，以及加载它们
花了多长时间。

📂 组织你的插件 *lazy.nvim-🚀-usage-📂-structuring-your-plugins*

有些用户可能想把插件 spec 拆分到多个文件中。这样你就可以使用
一个 Lua 模块，而不必把 spec 表传给 `setup()`。来自
**module** 以及任何顶层 **sub-modules** 的 spec 会被合并到
最终的 spec 中，因此你不需要在主插件文件中添加对
其他文件的 `require` 调用。

采用这种方式的好处：

- **添加**新的插件 spec 很简单。只需在你的 plugins 模块中新建一个文件。
- 允许对**缓存**你所有的插件 spec。当你有大量较小的插件 spec 时，这一点会变得很重要。
- spec 的变更在更新后会被自动**重新加载**，因此 `:Lazy` UI 始终是最新的。

示例：

- `~/.config/nvim/init.lua`

>lua
    require("lazy").setup("plugins")
<

- `~/.config/nvim/lua/plugins.lua` 或 `~/.config/nvim/lua/plugins/init.lua` **（此文件是可选的）**

>lua
    return {
      "folke/neodev.nvim",
      "folke/which-key.nvim",
      { "folke/neoconf.nvim", cmd = "Neoconf" },
    }
<

- `~/.config/nvim/lua/plugins/*.lua` 中的任何 lua 文件都会被自动合并进主插件 spec

想看真实的示例，可以查看 LazyVim
<https://github.com/LazyVim/LazyVim>，更具体地说：

- lazyvim.plugins <https://github.com/LazyVim/LazyVim/tree/main/lua/lazyvim/plugins> 包含了所有将被加载的插件 spec


↩️ 导入 SPEC、配置与 OPTS

作为 spec 的一部分，你可以添加 `import` 语句来导入额外的插件
模块。以下两种 `setup()` 调用是等价的：

>lua
    require("lazy").setup("plugins")

    -- 等同于：
    require("lazy").setup({{import = "plugins"}})
<

要从某个插件导入多个模块，请为每个 import 额外添加一个 spec。
例如，要导入 LazyVim 的核心插件以及一个可选插件：

>lua
    require("lazy").setup({
      spec = {
        { "LazyVim/LazyVim", import = "lazyvim.plugins" },
        { import = "lazyvim.plugins.extras.coding.copilot" },
      }
    })
<

当你导入 spec 时，只需在本地 spec 中为同一个插件添加一个 spec，
并加入任何你想覆盖/合并的键，就可以覆盖它们。

`opts`、`dependencies`、`cmd`、`event`、`ft` 和 `keys` 总是会与
父级 spec 合并。其他任何属性都会覆盖父级
spec 中的同名属性。

8. 🔥 开发者                                      *lazy.nvim-🔥-developers*

为了让用户更容易安装你的插件，你可以在你的仓库中
包含一个软件包 spec </packages>。


最佳实践                    *lazy.nvim-🔥-developers-best-practices*

- 如果你的插件需要 `setup()`，那么创建一个像下面这样的简单 `lazy.lua` 文件：
    >lua
          return { "me/my-plugin", opts = {} }
    <
- 纯 lua 库的插件应当用 `lazy = true` 来延迟加载。
    >lua
        { "nvim-lua/plenary.nvim", lazy = true }
    <
- 只要可能，请始终使用 `opts` 而不是 `config`。几乎从来都不需要
    使用 `config`。
- 只有当某个插件需要该依赖被安装 **并且**被
    加载时，才使用 `dependencies`。lua 插件/库在被
    `require()` 时会自动加载，所以它们不需要出现在 `dependencies` 中。
- 在 `build` 函数或 `*.lua` 构建文件内部，使用
    `coroutine.yield(msg:string|LazyMsg)` 来显示进度。
- 不要在你的 build 函数中更改 `cwd`，因为构建是并行运行的，
    更改 `cwd` 会影响其他构建。


构建                             *lazy.nvim-🔥-developers-building*

spec 的 **build** 属性可以是以下任一形式：

- `fun(plugin: LazyPlugin)`：一个用于构建插件的函数。
- `*.lua`：一个用于构建插件的 Lua 文件（例如 `build.lua`）
- `":Command"`：一条 Neovim 命令
- `"rockspec"`：这会在插件目录中运行 `luarocks make`
    该值会由 `rockspec` 软件包 </packages> 源自动设置。
- 任何其他 **string** 都会作为 shell 命令运行
- 上述任意项的 `list`，用于运行多个构建步骤
- 如果没有指定 `build`，但存在 `build.lua` 文件，则会改用该文件。

build 函数和 `*.lua` 文件会在协程中异步运行。使用
`coroutine.yield(msg:string|LazyMsg)` 来显示进度。

让出执行权还会把下一次 `coroutine.resume()` 调度到下一个
tick，因此你可以执行耗时较长的任务而不会阻塞 Neovim。

>lua
    ---@class LazyMsg
    ---@field msg string
    ---@field level? number vim.log.levels.XXX
<

使用 `vim.log.levels.TRACE` 可以只把消息作为任务的 **status**
消息显示。



Minit（最小化 init） *lazy.nvim-🔥-developers-minit-(minimal-init)*

**lazy.nvim** 自带一些内置功能，帮助你为你的插件
创建一个最小化的 init。

我主要把它用于测试，以及帮助用户创建 `repro.lua`。

以 **headless** 模式运行时，**lazy.nvim** 会把所有消息记录到
终端。更多信息参见 `opts.headless`。

**minit** 会安装/加载你的所有 spec，并且总会同时运行一次
